## 硬性纪律

1. **不许改产品代码**（`SpectreReplay\`、`tools\`）。只写 `docs\audit\` 下你自己那份。
2. **每条发现必须有行号 + 代码证据**。读不到原文件就不要写。
3. **先排除「设计使然」再报**。本项目大量行为在注释里写明了理由（如刻意吞异常、
   刻意 Private=false、刻意默认关的开关）。注释与代码冲突时，**冲突本身**就是一条发现。
4. **不报风格问题**（命名、空行、用 var 还是显式类型）。只报：真 bug、隐性问题、
   脆弱代码（一改就碎 / 依赖未文档化的假设）、版本适配风险、注释与代码不符、
   结构性问题（循环依赖、职责错位、重复实现）。
5. **不做无限深入**：每个文件读一遍，可疑处追到能下判断为止；写进报告再往下。
6. 严重度口径：
   - P0 崩溃/静默数据损坏/存档或回放被写坏（数据安全）
   - P1 功能在常见路径上失效、状态泄漏（关了还生效）、线程/GUI 崩溃
   - P2 边界条件下失效、性能热点、错误被吞掉导致难排查
   - P3 可维护性/注释漂移/结构性建议
