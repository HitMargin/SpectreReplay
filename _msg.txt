修复取消渲染后下一次「时钟全炸」；清掉「实时渲染」的幽灵文案

## 一、时钟全炸（用户报）

根因不是取消路径没清干净，而是清理**做失败了却装作成功**，外加一个会归零的除数。

`UnscaledDeltaPin.Uninstall()` 原实现：

    foreach (IDisposable d in detours)
    {
        try { d.Dispose(); }
        catch (Exception ex) { Debug.Log(...); }   // 吞掉
    }
    detours.Clear();                               // 不管成没成都清空

取消渲染时协程被 yield break 打断，TearDown 在**场景切换途中**跑（渲染第一步
就是 SwitchToPlayMode 重开关卡），此时 MonoMod 的原生 detour Dispose 很容易
因目标已被卸载而抛。那个 detour **仍然挂在 Time.unscaledDeltaTime 上，
但我们把它从列表里删了** —— 再也不知道它存在，也永远撤不掉。

下一轮 Install 看到 Count == 0，正常装新 detour ⇒ 旧那层成了永久接管者，
读的却是新一轮的静态字段。

而 `PinnedDelta` 当时是 `1f / Time.captureFramerate`，收尾早已把
captureFramerate 还原成 0 ⇒ 1/0 = Infinity ⇒ 星球位置 NaN。两次失效叠在一起，
就是用户看到的现象。

修法两处，缺一不可：
  ① 撤不掉的 detour **留在列表里**（带一次重试），不再连同 Clear 一起丢弃；
     Install 发现残留时先尝试撤销，撤不掉则明确放弃本轮钉扎并告警
     —— 宁可成片不够"确定性"，也不能静默产出 NaN。
  ② 钉扎位移改用 `armedFps` 帧率快照，安装时读一次，之后不再碰
     Time.captureFramerate。

判据 PinStateCheck 三条，各自守一半：
  · Uninstall 的 Add(d) 必须在 Clear() **之后**（顺序错了等于白做）
  · Install 发现残留后必须先撤销，不能直接 return
  · PinnedDelta / TickFrame / CurrentDelta 不得以 Time.captureFramerate 为除数

MUT-PIN1（撤不掉的直接丢掉）、MUT-PIN2（退回 captureFramerate 当除数）
各证一条，实测各红 1 条。

## 二、「实时渲染」幽灵文案（用户截图指出）

开始渲染下面那句写着「离线渲染：…耗时更长但画面与原回放完全一致」——
它在跟**实时渲染**对比，而那个模式早就不存在了。用户问"实时渲染我记得都没了
啊，为什么还会显示"。

不止这一句。`render.on.tip` 说"既不会边玩边录也不会离线渲染"、
`render.start.tip` 说"开始离线渲染"。全部改写为不提及已删模式的说法，
并重新翻译 12 种语言。

顺带删掉 28 个确认零引用的死键（`render.mode*`、`render.note.live`、
`render.offline_target`、`render.state.*`、`render.err.*` 全家、
`render.progress`、`render.status`、`render.duplicate_when_late`）。
每个都做了全仓精确搜索确认无人引用——`.tip` 类除外（Gui.Tip 会隐式拼
`labelKey + ".tip"`，那些是活的）。

`render.err.need_level` 一并删除：它是旧 UI 文案表的键，运行时不走它；
真正在用的是 LocalizationManager 里的 `rendervideo.need_level`（14 语言齐全）。

全部修正，MUT-P7 与 MUT-V15 实测重新变红（3 条 / 8 条）。
